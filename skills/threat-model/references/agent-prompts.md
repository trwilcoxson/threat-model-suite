# Agent Spawn Prompt Templates

All prompt templates for agents spawned during threat model assessments. Substitute `{output_dir}`, `{project_root}`, and `{refs_dir}` with actual paths before use. `{refs_dir}` is the skill's own `references/` directory (an absolute path) — do not copy reference files anywhere. Every agent is spawned by its own `name` as `subagent_type`; the agent definition (personality + phase instructions) loads automatically, so no prompt tells an agent to read its own definition from a file.

Follow the skill's Phase 7 instructions and the Risk & analytical acceptance gate: produce the L4 threat overlay with TM-NNN linkage, and EACH analytical/communication visual whose precondition holds (STRIDE matrix always; heat map when findings are scored; ATT&CK layer when any finding has a MITRE id; RBAC matrix when ≥2 roles; SBOM when a dep has a manifest; auth sequence when there is auth; attack tree + attack flow per declared kill chain when ≥3 exist). Stamp each companion diagram's version line with `| Type: {kind}` exactly as analytical-visuals.md specifies so the eval detects it. Write 07-final-diagram.md to {output_dir}/. Update visual-completeness-checklist.md with risk overlay completion status. The project root is {project_root}. RENDER-TIER CONSTRAINT: if the render preflight declared the browser-free fallback tier active (`TM_RENDER_TIER=fallback` — a locked-down/air-gapped host with no headless browser), keep every diagram label PLAIN single-line text: no `|md|` / multi-line / `\n` / `<br>` / foreignObject labels, because the browser-free rasterizer (resvg) silently blanks them. On the primary (cached-browser) tier, full-fidelity multi-line labels are fine. EXECUTION LOG: At the end of 07-final-diagram.md, include an ## Execution Log section — document process health, risk annotations applied (count by severity), analytical visuals produced vs marked N/A, attack paths overlaid, any findings that could not be mapped to diagram components, and self-assessed overlay quality.

## Solo — report-analyst prompt

> Generate the consolidated security assessment report from the threat model outputs. OUTPUT DIRECTORY: {output_dir}/. AVAILABLE INPUTS: 01-reconnaissance.md through 08-threat-model-report.md (note: 08 is a summary — the full report structure comes from the template), plus coverage.json (the coverage ledger — source the report's Coverage Profile / Open Questions / Known Limitations from it). No team agents ran — this was a solo assessment. Skip Sections X and XI in the report structure and note in Assumptions that privacy and compliance assessments were not performed. FIRST: Read the report template at {refs_dir}/report-template.md. Follow the template EXACTLY. You have Bash access. GENERATE ALL FOUR FORMATS using your docx, pdf, pptx, and frontend-design skills: 1. report.html 2. report.docx 3. report.pdf 4. executive-summary.pptx. CRITICAL: You MUST generate all four files yourself. When installing Python packages, ALWAYS use a venv: python3 -m venv /tmp/report-venv && source /tmp/report-venv/bin/activate && pip install python-docx python-pptx reportlab Pillow. Render every diagram artifact through the render seam (dispatches `.mmd`→mermaid-cli, `.d2`→the offline D2 toolchain; emits a PNG for docx/pdf/pptx and, for each `.d2`, an offline `.svg` to inline into report.html): `bash {refs_dir}/../scripts/render_diagrams.sh {output_dir} {refs_dir}`. The seam is behavior-identical to the old inline `mermaid-cli` call for `.mmd`, and it fails loud on a missing renderer, an unknown extension, a remote icon URL, or a blank raster — do not hand-roll an `npx` render. The project root is {project_root}. HTML GENERATION RULES (MANDATORY): (1) Embed each diagram either as the offline inline SVG the seam produced for a `.d2` (paste its `<svg>…</svg>` directly into the HTML — crisp, zoomable, no browser at render time) OR as a pre-rendered PNG using <img src="structural-diagram.png"> / <img src="risk-overlay-diagram.png"> — NEVER use Mermaid CDN (mermaid.js) for client-side rendering. (2) NEVER write <\/script> in HTML output — this JS-only escape breaks the HTML parser. Always write </script> literally. (3) Do not use defer/async on script tags that inline JS depends on. (4) All CSS and JS must be inline in the single HTML file (no external dependencies except the PNG images). BEFORE DECLARING DONE: Verify all files exist and are non-empty. For report.html, additionally verify: grep for '<img' OR '<svg' to confirm a diagram embed exists (inline SVG counts), grep for 'mermaid' to confirm no CDN usage, grep for '<\\/script>' to confirm no broken escapes. GENERATION LOG (MANDATORY): After all files are generated, write {output_dir}/report-generation-log.md with: (1) a table of each deliverable (report.html, report.docx, report.pdf, executive-summary.pptx, structural-diagram.png, risk-overlay-diagram.png) with status (SUCCESS/FAILED), file size, and any errors encountered; (2) diagram rendering results — fold in the render seam's per-diagram engine + PNG tier + fidelity ledger from `{output_dir}/.render-tiers` (e.g. `d2 | risk-overlay-diagram.png | fallback/resvg/plain-labels`) plus any render warnings; (3) HTML validation check results (each grep check: PASS/FAIL with details); (4) corrections applied from validation-report.md (if team mode); (5) any issues encountered during generation and how they were handled; (6) overall self-assessed quality (HIGH/MEDIUM/LOW) with justification.
